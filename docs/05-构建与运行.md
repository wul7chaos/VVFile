## 1. 环境基线（本机实测）

| 组件 | 版本 / 路径 |
| --- | --- |
| JDK | Temurin 21.0.12 (`JAVA_HOME` 已配置) |
| Android SDK | `C:\Users\19256\AppData\Local\Android\Sdk` |
| platforms | android-36、android-37.0 |
| build-tools | 35.0.0 / 36.0.0 / 37.0.0 |
| Gradle | 8.14.3（wrapper 发行版已缓存于 `~/.gradle/wrapper/dists`） |

若机器上没有这个 NDK 版本，装一个同名版本或改 `ndkVersion` 即可，无需 CMake。

`local.properties` 不提交，由脚本或 Android Studio 生成：

```properties

```

## 3. 连接 MuMu

MuMu 的 adb 端口由 `MuMuManager info -v 0` 的 `adb_port` 决定（本机 16384）：

```powershell
.\scripts\adb-connect.ps1
# 或
& 'C:\Program Files\Netease\MuMu\nx_main\adb.exe' connect 127.0.0.1:16384
```

多个设备时统一指定 serial：

```powershell
adb -s 127.0.0.1:16384 shell ...
```

## 4. 安装与启动

```powershell
.\scripts\install.ps1
# 内部执行：
#   adb install -r -t app-debug.apk
#   adb shell am start -n com.vvfile.app/.MainActivity
```

首次启动需要授予"所有文件访问权限"（debug 包名带 `.debug` 后缀）：

```powershell
adb shell appops set com.vvfile.app.debug MANAGE_EXTERNAL_STORAGE allow
```

release 包则把包名换成 `com.vvfile.app`。

root（MuMu 需在设置中开启 ROOT）：

```powershell
adb shell su -c id
```

## 5. 日志与调试

```powershell
adb logcat -s VVFile:V AndroidRuntime:E
adb shell dumpsys activity activities | Select-String com.vvfile
```

崩溃栈默认写入 logcat；debug 包可导出到 `/sdcard/Android/data/com.vvfile.app/files/crash/`（P1）。

## 6. 签名与发版

- debug 使用 Android 默认调试证书（包名 `com.vvfile.app.debug`）。
- release 签名优先读仓库根目录的 `keystore.properties`（已 gitignore），
  其次读环境变量，两处都没有就回退 debug 签名，仅用于本地验证：

```properties
# keystore.properties（不入库，路径用正斜杠）
storeFile=C:/Users/19256/vvfile-signing/release.jks
storePassword=...
keyAlias=vvfile
keyPassword=...
```

```powershell
# 或者用环境变量
$env:VVFILE_KEYSTORE_FILE='C:/keys/vvfile.jks'
$env:VVFILE_KEYSTORE_PASSWORD='...'
$env:VVFILE_KEY_ALIAS='vvfile'
$env:VVFILE_KEY_PASSWORD='...'
.\gradlew.bat :app:assembleRelease
```

- 版本号由 tag 决定：`versionName` = tag 去掉 `v`，`versionCode` = 主*10000+次*100+补丁。

```powershell
git tag v1.0.1
git push origin v1.0.1        # 触发 .github/workflows/release.yml
```

CI（GitHub Actions，`ubuntu-latest`）做四件事：装 JDK 21 + android-36 + build-tools 36 +
NDK 29.0.14206865 → 跑 `:app:testDebugUnitTest` → `:app:assembleRelease`（从 Secrets
解出 keystore）→ `gh release create` 把 APK 与 sha256 挂到 Release。也可以在 Actions
页面 `workflow_dispatch` 手动填版本号跑一次。

需要在仓库 Secrets 里配：`VVFILE_KEYSTORE_BASE64`（jks 的 base64）、
`VVFILE_KEYSTORE_PASSWORD`、`VVFILE_KEY_ALIAS`、`VVFILE_KEY_PASSWORD`。

## 7. 常见问题

| 现象 | 处理 |
| --- | --- |
| `SDK location not found` | 创建 `local.properties` 或设置 `ANDROID_HOME` |
| Gradle 下载超时 | 使用已缓存发行版；必要时配置镜像 |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | `adb uninstall com.vvfile.app` 后重装 |
| 模拟器 adb 显示 offline | `adb kill-server` 后重新 `connect 127.0.0.1:16384` |
| 无法读取 `/data` | 确认 MuMu 已开启 root，且应用获得 su 授权 |
| 抽屉显示 root 未检测 | 本机 MuMu 6.8.8 / Android 15 镜像即使 `root_permission=true`，整机重启后仍可能不存在 `su`；此时应用按无 root 模式工作。换支持 root 的镜像或真机验证 root 用例 |
| 列表空白但目录有文件 | 检查"所有文件访问权限"是否授予 |
