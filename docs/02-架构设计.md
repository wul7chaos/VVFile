# 架构设计

## 1. 总体结构

单模块 `:app`，内部按职责分包（core / data / feature / ui）。首版不拆 Gradle 模块，
避免构建复杂度；当功能继续膨胀时按 `feature/*` 平移即可成为独立模块。

```
┌─────────────────────────────────────────────────────┐
│ UI (Compose)                                        │
│  BrowserScreen  EditorScreen  TerminalScreen  ...   │
│      │ StateFlow / UiEvent                          │
│  ViewModel (browser, editor, terminal, apps, ...)    │
└──────────────────────────┬──────────────────────────┘
                           │ suspend / Flow
┌──────────────────────────▼──────────────────────────┐
│ Domain / Data                                       │
│  FileRepository    ShellExecutor    PrefsRepository │
│  CopyEngine        ZipService       AppRepository   │
│  FileEntry model   PathUtils        RootChecker     │
└──────────────────────────┬──────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────┐
│ Platform                                            │
│  java.nio.file  ·  ProcessBuilder(su/sh)  ·  SAF    │
│  PackageManager ·  DataStore ·  FileProvider        │
└─────────────────────────────────────────────────────┘
```

## 2. 分层职责

### UI 层

- 全部 Compose，无 XML 布局（`res/xml` 仅 FileProvider 路径与备份规则）。
- 一个顶层 `VVFileApp` 负责主题、导航、全局 Snackbar。
- 每个功能一个 `*Screen` + `*ViewModel`；Screen 不直接碰 IO。
- 事件用 `Channel<UiEvent>` 暴露给 UI（Toast/Snackbar/弹窗），状态用
  `StateFlow<UiState>`，禁止在 Composable 内启动协程做 IO。

### 领域/数据层

| 组件 | 职责 |
| --- | --- |
| `FileEntry` | 文件条目值对象：name/path/isDir/size/mtime/permissions/isSymlink |
| `FileRepository` | 列目录、stat、exists、canRead/canWrite；根据路径自动选 NIO 或 shell |
| `CopyEngine` | 复制/移动/删除的批量执行器，输出 `OperationProgress`，支持取消 |
| `ZipService` | ZIP 压缩/解压，Zip Slip 防护，进度回调 |
| `ShellExecutor` | `sh -c` / `su -c` 执行，超时、输出上限、退出码 |
| `RootManager` | root 可用性检测、su 命令解析、授权状态缓存 |
| `PrefsRepository` | DataStore 封装，暴露 `Flow<Settings>` |
| `AppRepository` | PackageManager 查询、APK 导出、卸载 |
| `PathUtils` | 路径规范化、父子判断、扩展名/MIME、人类可读大小 |
| `StorageStats` | StatFs 分区容量、目录统计 |

### 平台能力

- **直接 IO**：`/storage/emulated/0`、应用私有目录、`/sdcard` 别名。
- **root 通道**：直接 IO 抛 `AccessDeniedException`/`IOException` 且路径属于
  root 域时，改走 `su -c` 执行；**未获得 root 直接报错，不接入 Shizuku、ADB
  shell、无障碍等提权方案**。内置终端的非 root 会话只是应用自身 uid 的 `sh`，
  不构成提权。
- **权限**：`MANAGE_EXTERNAL_STORAGE`（Android 11+）+ 旧版读写权限；
  首次启动检测，未授予时顶部横幅引导，功能降级到应用私有目录。
- **FileProvider**：分享文件必须经 `content://` URI，authority
  `com.vvfile.app.fileprovider`。

## 3. 双窗格状态模型

```kotlin
data class PaneState(
    val id: PaneId,                 // LEFT / RIGHT
    val path: String,
    val entries: List<FileEntry>,
    val selected: Set<String>,
    val history: List<String>,
    val historyIndex: Int,
    val sort: SortSpec,
    val filter: String,
    val loading: Boolean,
    val error: String? = null,
)
```

- `BrowserViewModel` 持有 `leftPane` / `rightPane` / `activePane`，
  通过 `StateFlow<BrowserUiState>` 汇总。
- 每个窗格独立 `Job`，切换目录会取消上一个目录的加载任务。
- 目录加载：`Dispatchers.IO` 中 `Files.newDirectoryStream`，大目录（> 5000 项）
  分批 emit，UI 用 `LazyColumn` 稳定 key = 绝对路径。

## 4. 文件操作执行模型

```
用户操作 → OperationRequest(Add/Replace/Skip, sources, targetDir)
        → CopyEngine.run(request) : Flow<OperationProgress>
             ├─ 预检：源存在、目标可写、空间足够、同路径检查
             ├─ 逐项执行（NIO walkFileTree 或 shell cp -a）
             ├─ 冲突：挂起等待 UI 决策（CompletableDeferred）
             └─ 结果：成功数/失败明细/耗时
        → 完成后刷新受影响窗格
```

- **进度**：按已处理字节 / 总字节（NIO 可精确；root 通道按文件计数估算）。
- **取消**：协程 `cancel()`，复制中途删除已写的目标临时文件；移动取消不回滚已移动项。
- **临时文件**：复制到 `目标目录/.vvfile_tmp_<uuid>`，完成后原子 rename；
  启动时清理超过 24h 的临时文件。
- **跨窗格移动**：同一分区用 `Files.move`；跨分区先复制再删源。

## 5. Root / Shell 设计

```kotlin
class ShellExecutor {
    suspend fun exec(cmd: String, asRoot: Boolean, timeoutMs: Long = 30_000): ShellResult
}
```

- 命令固定用 `sh -c` / `su -c` 包裹，避免拼接注入；文件路径参数用单引号转义
  （`'` → `'\''`）。
- 输出上限 1 MB，超出截断并标记；超时 kill 进程树。
- 常用 root 文件操作直接走 shell：`ls -la`、`stat`、`cp -a`、`mv`、`rm -rf`、
  `mkdir -p`、`chmod`、`find`。**不使用** `Runtime.exec(String)` 拆分，统一传数组。
- root 授权结果缓存到进程内；用户拒绝后本次启动不再自动弹窗（设置可改）。

## 6. 终端实现

- **真 PTY**：`/dev/ptmx` + `fork` + `setsid` + `execvp` 全在 `app/src/main/cpp/termux.c`
  （Termux `terminal-emulator` 的 JNI，Apache-2.0），编成 `libtermux.so`，只出
  `arm64-v8a` / `x86_64` 两个 ABI，每个约 9 KB。
- 进程、仿真的分工：
  - `com.termux.terminal.TerminalSession`：起子进程、三条线程（PTY 读 / PTY 写 / waitpid）、
    两个 `ByteQueue`，所有回调切主线程。
  - `com.termux.terminal.TerminalEmulator`：完整 VT 解析（CSI/OSC/APC、SGR 256 色、
    alternate screen、鼠标上报、sixel），5000 行回滚。
  - `com.termux.view.TerminalView`：Canvas 渲染 + 自带选区手柄 + IME/硬件键接入。
- App 侧只做三层适配：
  - `PtyShell`：启动参数（`/system/bin/sh`、cwd、env、`PS1`）与 `$ENV` 启动脚本
    （补 `sudo` 函数）。
  - `TerminalViewModel`：会话生命周期、粘滞 Ctrl/Alt、`^C` 直发 0x03、按提示符判定 root。
  - `TerminalScreen`：MT 式顶栏与两排功能键，中间嵌 `AndroidView(TerminalView)`。
- 不做「无 PTY 折中」：不需要自己解析 ANSI、不需要哨兵回传 cwd、不需要自建历史。
- 不引入 Termux 的 `termux-shared`（GPLv3），也不搬 bootstrap；exec 的是系统分区的 sh，
  因此 `targetSdk = 36` 不受 W^X 影响。

## 7. 并发与生命周期

- 所有 IO 在 `Dispatchers.IO`；UI 状态更新回主线程。
- ViewModel 使用 `viewModelScope`；长任务（复制/解压）放入
  `OperationRegistry`（应用级单例），页面退出不中断，通知栏展示进度（P1）。
- 目录监听不做 `FileObserver` 全量监听（耗电），改为页面 `ON_RESUME` 刷新 + 手动刷新。

## 9. 错误处理约定

- 数据层抛领域异常：`PathAccessDenied`、`PathNotFound`、`NoSpaceLeft`、`RootUnavailable`。
- ViewModel 捕获并转成用户可读文案 + 可执行动作（去授权 / 重试 / 跳过）。
- 所有批量操作返回 `OperationResult(success, failures: List<Failure(path, reason)>)`，
  UI 展示前 5 条并可复制完整清单。
