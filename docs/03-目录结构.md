原则：**按职责分层，按功能分包；一个文件只做一件事；命名即文档。**

## 写作用域

目录按 owner 划分，同一时间只允许一个代理写入。完整矩阵、共享文件清单与
分支/worktree 规则见 [`08-子代理并行开发规范.md`](08-子代理并行开发规范.md)。
要点：

- 共享文件（根构建脚本、Manifest、版本目录、`ServiceLocator`、`Routes`）只由 Lead 修改。
- 字符串资源按功能拆分：`strings_ui.xml`、`strings_term.xml`、`strings_tools.xml`，
  避免所有人在 `strings.xml` 上冲突。
- 子代理在 `VVFile.wt\<name>` 的独立 worktree 工作，不直接提交 main。

## 命名与编码约定

- 包名全小写；类名 UpperCamelCase；Compose 组件名 = 文件名。
- ViewModel 暴露 `uiState: StateFlow<XxxUiState>` 与 `events: Flow<XxxEvent>`。
- 仓库方法一律 `suspend`，批量操作返回 `Flow<Progress>` 或 `OperationResult`。
- 资源命名：`ic_vv_*`（图标）、`bg_*`、`color_*`；字符串集中在 `strings.xml` 并带注释。
- 禁止在 UI 层出现 `java.io.File` 直接操作（统一走仓库）。
- 每个 feature 包只依赖 `core` 与 `data`，feature 之间不互相 import。

## 文件规模红线

| 类型 | 建议上限 | 超出处理 |
| --- | --- | --- |
| Composable 文件 | 300 行 | 拆子组件 |
| ViewModel | 250 行 | 拆 use case |
| 仓库实现 | 400 行 | 按能力拆接口 |
