# 子代理并行开发规范

> 目标：多个子代理（Agent Teams）同时推进 VVFile，**互不覆盖、互不阻塞、可随时集成**。
> 本文件是并行开发的唯一规则来源；与 `02-架构设计.md`、`03-目录结构.md` 冲突时以本文件为准。

## 1. 基本原则

1. **一个文件同一时间只有一个写者**。写作用域按目录/文件预先分配（见 §3）。
2. **契约先行**：跨模块接口在 W0 冻结，冻结后只能由 Lead 变更（见 §5）。
3. **任务驱动**：没有任务卡就不写代码；任务卡必须写清写作用域、验收标准、依赖。
4. **分支隔离**：每个子代理在自己的 git worktree + 分支工作，**不直接改 main**。
5. **集成权归 Lead**：只有 Lead 合并分支、改共享文件、跑最终构建与安装。
6. **设备串行**：MuMu 模拟器是独占资源，同一时刻只允许一个代理安装/操作（见 §9）。
7. **小步提交**：一次提交只做一件事，提交信息带任务号。
8. **特殊权限只走 root**：禁止引入 Shizuku、ADB shell、无障碍等提权通道或依赖；
   非 root 能力仅限应用自身权限，root 能力统一经 `su`。

**硬规则**

## 4. 目录与分支映射

```
C:\Users\19256\Documents\Projects\VVFile                 # main / Lead
C:\Users\19256\Documents\Projects\VVFile.wt\fs-core      # feat/fs-*
C:\Users\19256\Documents\Projects\VVFile.wt\ui-shell     # feat/ui-*
C:\Users\19256\Documents\Projects\VVFile.wt\root-shell   # feat/root-*
C:\Users\19256\Documents\Projects\VVFile.wt\tools        # feat/tools-*
C:\Users\19256\Documents\Projects\VVFile.wt\qa           # test/qa-*
```

- worktree 由 Lead 创建：`git worktree add ..\VVFile.wt\<name> -b <branch> main`。
- 子代理只在自己的 worktree 内读写，**不得进入主工作区或其他 worktree**。
- 分支命名：`feat/<area>-<short-desc>`、`test/<area>-<short-desc>`。
- 同步：合并前 `git fetch . main && git rebase main`；冲突由**该分支作者**解决。
- 完成后推送/保留分支，通知 Lead 合并；Lead 用 `--no-ff` 合并并跑集成构建。
- 禁止：`git push --force`、直接 commit 到 main、删除他人分支、修改 git 历史。

## 6. 任务板流程

**Lead 建卡 → 子代理领取 → 实现 → 自检 → 完成并留言。**

建卡必填：

- `subject`：`[W2][fs-core] CopyEngine 支持取消与冲突策略`
- `description`：目标、涉及文件、验收命令、依赖卡 id、设备需求
- `write_scopes`：精确到目录/文件（如 `app/src/main/java/com/vvfile/app/data/file/`）
- `blocked_by`：必须完成后才能开始的卡

领取规则：

1. 用 `team_task_list` 找 `ready` 且未领取的卡；
2. `team_task_get` 拿 revision；
3. `team_task_update(action=claim, expected_revision=...)`；
4. 只做卡内写作用域的事，发现需要越界 → 停手，发消息给 Lead 建新卡或改卡。

完成规则：

- 附：变更摘要、验证方式（命令/截图路径）、遗留问题；
- 写作用域外零改动（`git diff --stat` 自证）；
- 构建/测试通过后才 `complete`。

## 8. 集成节奏

- 每天固定 2 个合并窗口（如 12:30 / 18:30），Lead 合并并跑：
  ```powershell
  .\gradlew.bat :app:assembleDebug :app:testDebugUnitTest
  ```
- 合并顺序：契约/内核 → UI → 工具 → 测试。
- 每次合并后 Lead 打 tag：`w1`, `w2` …，便于回滚。
- 集成构建失败：**最后合并者**负责 30 分钟内修复，否则 Lead 回滚该合并。

## 9. 设备与构建资源

- MuMu 同一时间只能有一个代理执行 `install` / UI 操作。
- 需要设备时，先在任务卡勾选 `device` 并在团队消息里申请"设备窗口"；
  Lead 按时间片分配（默认 20 分钟/人）。
- 截图统一输出 `docs/shots/<agent>-<feature>-<timestamp>.png`，避免覆盖。
- 代理可跑 `compileDebugKotlin`，**完整 assemble/install 只在 Lead 的集成窗口**执行，
  避免 Gradle 锁与 APK 互相覆盖。
- 模拟器 adb 端口：`127.0.0.1:16384`（见 `scripts/adb-connect.ps1`）。

## 11. 完成定义（DoD）

每个代码任务必须同时满足：

- [ ] 只改任务卡写作用域内的文件
- [ ] `./gradlew :app:compileDebugKotlin` 通过（自己 worktree）
- [ ] 新增/修改逻辑有对应单测（纯逻辑）或手工验证记录（UI/设备）
- [ ] 无新增 TODO 占位（除非卡内明确允许）
- [ ] 提交信息：`<type>(<area>): <summary> [T-xx]`
- [ ] 任务卡留言包含验证证据

## 12. 常见混乱与对策

| 现象 | 根因 | 对策 |
| --- | --- | --- |
| 两人同时改 `strings.xml` | 资源未拆分 | 按 feature 拆 `strings_*.xml`，只由对应 owner 写 |
| 合并后编译失败 | 契约被私改 | 契约冻结 + Lead 集成构建门禁 |
| 同一文件反复冲突 | 共用主工作区 | 强制 worktree + 分支 |
| APK 互相覆盖 | 多人同时 install | 设备窗口串行化 |
| 大量格式化 diff | 全文件重排 | 只做最小 diff，禁止批量 reformat |
| 任务卡互相等待 | 依赖未声明 | 建卡必须写 `blocked_by` |
| 子代理"顺手"改别人文件 | 边界不清 | 写作用域表 + DoD 自证 diff |
